## Full local acceptance

Requires idle owner PostgreSQL, no active owner DAG runs/batches, periodic/replay
DAGs paused. Never pause/stop owner services without an agreed maintenance window.
With owner Airflow running, Docker needs >=6GiB total and >=3GiB measured container
headroom. With an explicitly approved temporary owner-Airflow stop, >=3.5GiB total
and >=3GiB headroom are still required. Stop other OLD validated test environments
using their matching harness first; do not delete their volumes.

For >=6GiB and adequate headroom, leave owner Airflow running and execute:

```powershell

$idMatch = [regex]::Match(($created -join "`n"), 'id=([0-9a-f]{12});')
```

## What PASS means

Final message `M08B acceptance PASS ... owner signature unchanged`, exit0, and
`status`, `teardown`, `protected_check` all PASS in:

```powershell
$result = Get-Content "runtime/isolated/m08a-$testId/evidence/result.json" -Raw | ConvertFrom-Json
$result | Select-Object status,teardown,protected_check
$result.s02
```

Continuous additionally requires each of website_polling, ebay_polling, etsy_inbox
and etsy_recovery to have >=2 actual successful SCHEDULED runs. Each generated
wave must be published with matching scoped identities, lines, quantities, money,
states and source times. A notified Etsy order must appear before recovery is
enabled; a deliberately unnotified one must not, then must be recovered. Final
source SQL/HTTP reads must agree with warehouse; every observed history version
has raw evidence, and repeated acquisition/replay increases raw audit without
inflating 12 logical versions. Failed/unresolved work cannot be hidden as PASS.

Scheduler/publication/drain waits share a1800s budget from campaign start. Other
synchronous commands have individual timeouts; finite operation counts bound
generation. This is NOT a hard30-minute process kill; CI additionally caps its
whole job at45 minutes. Intermediate steps/wait messages are expected; a timeout is FAIL.
Do not equate `check PASS` with full acceptance. No manual per-cycle DAG trigger,
collector or dbt command is required during the scheduled generation phases.
The final explicit CLI phase is separately labeled replay evidence.
The final-code ending protocol creates a private drain signal, waits until all
four serialized timetables are NullTimetables, lets UNPAUSED in-flight runs finish,
checks every terminal run is successful, THEN pauses test DAGs. It does not
restart Airflow, clear tasks, reset budgets or force success. Source generation
has stopped; existing warehouse work is allowed to finish during maintenance.

Default teardown removes only TEST containers/network, retaining test volume,
dbt artifacts, private configuration, append-only `s02-ledger.jsonl` and command
logs. Ledger is accessible only to host/test code, never mounted into services.
S02 marketplace state is in memory in B: restart durability/recovery is NOT yet
implemented/tested and remains C work. No full vendor history guarantee, refunds,
delivery SLA, throughput or latency percentiles are claimed.
The acceptance scope is finite and automatically stopped at the end. The OWNER
dashboard must keep its previous data; it will not show S02 orders from this
isolated database. Continuous test phases are not an always-on demo service.

`python -m test_support.m08b stop --id $testId` is guarded teardown, not reset.
Do not run it concurrently with acceptance. CI-only `--ci` requires the owner
project COMPLETELY absent, including stopped containers/volumes/network; never use
it to bypass local protection. Integration CI runs the finite profiles on isolated
runners; adding YAML does not mean remote Actions has run. Stop before M08C.
